Abstract. This project investigates fixed-point bottle manipulation using a stationary RoboMaster EP chassis, its two-axis arm and gripper. A ROS 2 simulation and a Python hardware controller implement a home–pick–place–return sequence. Five simulation cycles met the defined acceptance criteria, and five recorded hardware runs completed their command sequences. Physical grasp success must be assessed separately from controller completion.

1. Objective and experimental setup

The task is to pick up an upright 550 ml water bottle from the ground, transfer it forward and release it at a designated location. The bottle contains 150 ml of water. Chassis motion and visual object detection are outside this experiment; pickup and placement positions are predefined.

The Jetson Orin environment uses ROS 2 Foxy, Gazebo 11 and MoveIt 2. Simulation reuses the jeguzzi/robomaster_ros model, with a simplified parallel gripper and rigid bottle. The assumed bottle dimensions are 227 mm × 64 mm, with a total simulated mass of 175 g. These values are modelling assumptions rather than measured material properties.

2. Control method

The simulation uses ROS 2 trajectory control. The hardware program uses the DJI Python SDK and explicit Cartesian targets, checking fresh position feedback after each movement. It confirms the gripper-open status before withdrawing from the placement point. Failures stop subsequent actions without an automatic release.

Home → Approach A → Lower & grip → Lift → Transfer to B → Lower & release → Return home

A 3 mm endpoint tolerance was adopted after supervised empty-path testing. The original B target at x = 236 mm repeatedly produced no forward progress near x = 208 mm. With operator approval, B was moved to x = 206 mm. Height recovery between long movement segments prevents downward error from being carried into the next segment.

4. Limitations and conclusion

The project demonstrates the simulated task and a functioning hardware command sequence. The simulation simplifies arm dynamics, gripper contact and bottle deformation. Hardware logs do not directly measure grip force, bottle pose or damage. Future work should label the physical outcomes against video evidence and unify the simulation and hardware backends behind one ROS 2 interface; the current hardware controller remains SDK-based.
